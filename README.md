# tv · 本地看图终端

TradingView 观感的 A 股看图工具，数据默认来自本机通达信文件。
**盘中走实时链路（TQ / 同花顺 / 东财 / 腾讯 / 通达信 MAC，实时请求最短间隔 300s；1 分钟档只读本地），收盘后回到本地 vipdoc**；
`TV_LIVE=0` 或 `TV_OFFLINE=1` 可退回纯离线（对表 / 无网机器）。核心图面为 K 线 + 成交量 + 缠论，
另提供画线、预警和可选的成交量分布（VP），技术指标可按需接入。

> **本仓库不含行情数据与凭据。** `data/vipdoc|tdx|tdx_xdxr`（拷贝模式下的可选快照）、
> `eq/fixtures`
> 的 K 线夹具、`eq/golden` 的 bar 级金标、`crates/*/tests/fixtures/*.http` 录播响应、`data/market`
> 缓存与 `data/symbols.json` 一律不入库（清单见 `.gitignore`）。clone 后：装好通达信客户端就能
> 直读它的行情目录（`./run.sh` 默认如此，零拷贝）；要建本地快照用 `tools/sync-data.sh` 或
> `TV_SYNC=copy ./run.sh`；`tools/restore-fixtures.sh` 还原 K 线夹具；夹具或金标不在位时，
> 对应的逐值对拍测试打印 SKIP 后跳过，不会把 `cargo test` 弄红。
> API key 只从环境变量（`HITHINK_FINANCE_API_KEY` / `HITHINK_API_KEY` / `THS_API_KEY`）或本机
> 凭据文件读，代码、夹具和 git 历史里都没有它。

顶栏还带：坐标切换（普通 / 对数 / 百分比）、磁吸十字光标；
成交量为独立副图，主图叠淡色水印与末根收盘价虚线。
主图左下角 OHLCV 图例行下的第二行是个股归属（`/api/stock-tags`）：**L2 行业**
（industry_catalog.json 通达信研究行业二级，按 `X+4 位 ref 前缀` 规则从成员的
L2/L3 归属反查）+ **概念题材**（**MAC 在线板块数据**，见下），悬停可看地区 / 风格 /
数据来源 / 抓取时间，无归属标的（指数 / ETF）该行自动隐藏。

> **题材来源为什么换了**：原来读本地 `data/tdx/block_gn.dat`，这份文件（以及通达信客户端
> 自己那份 `T0002/hq_cache/block_gn.dat`，md5 相同）**停在 2022-08-24**——000338 只有
> 「燃料电池/氢能源」，没有「AI智能体」「DeepSeek概念」；228 个概念块里没有 CPO、光模块、
> 机器人、低空经济。而同期 L2 行业是新的（catalog 11-01 重生成、`tdxhy.cfg` 10-29 更新）。
> TV-34 起题材改走 MAC（`0x1218` 个股所属板块 / `0x1231` 板块清单 / `0x122C` 成分股），
> 全量刷新落 `data/tdx/concepts_cache.json`（458 板块 / 6025 只 / 76184 条映射，约 50 秒），
> 刷新节奏：**每周第一次启动刷一次**——判据是日历周，根 `ts` 早于本周一 00:00（本地）才算过期，
> 启动检查一次、过期才后台刷；同一周内无论重启多少次都不再出网。
> 缓存里没有的个股再用 `0x1218` 单查一次（42 ms）并写回。
> 概念/地区/风格（type=3/4/5）同一节奏，风格块不再有独立的 30 分钟快周期——
> 厂商按自有节奏重算的那类标签最多滞后到上次刷新，界面「抓取时间」如实显示、不冒充实时。
> 旧 `block_gn.dat` 降为**回退**，且 `concept_source` 会标 `tdx_block_gn_legacy`，
> 图例行同步显示红色「题材为旧快照」——陈旧是事实，不静默冒充当前口径。
>
> MAC 的口径细节（都是实测踩出来的）：`0x1218` 的 head_flag 是 **1**（不是 0x1C）、
> `"Stock_GLHQ"` 必须补到 **21 字节**、响应是 27 字节头 + **GBK JSON**（前 4 个字段是字符串）；
> `0x1231` 的 `start` 是 **u16**；板块码要换算（`880564` → `20564`，直传**静默返回 0 行**）。
> 板块类型 3=地区 / 4=概念 / 5=风格 / 12=行业（**不是** easy_tdx 的 BoardType 编号），
> 行业仍走本地 catalog 没用这条路。
>
> 缓存文件另有三条**不变量**（TV-34 复查补的，`final_check` §5e 逐条设门）：
> ①键一律归一成 6 位代码——`sh600519` / `600519.SH` / `600519` 必须落在同一条上；
> 指数 / 板块 / ETF 查不到就走进程内 600 秒**负缓存**，**不写进文件**（不污染全量快照）。
> ②**根 `ts` 只有全量刷新能改**：单股补漏沿用旧根 ts、只给自己那条打 `fetched` 戳，
> 否则查一只股票等于宣称 6000 只刚抓完，并把下一次周刷整整数地推迟。
> 补漏的「读旧 → 合并 → 落盘」整段在 `FILE_LOCK` 内（锁外合并 = 两个并发补漏各基于同一份
> 旧快照写全量文件，后写的把先写的整条覆盖掉），而全量刷新**只能放锁后再点火**——
> `write_cache` 要拿同一把不可重入锁，持锁调用就是死锁。
> ③`TV_LIVE=0` 的语义是「这个进程一个 MAC 请求都不发」，所以单股查询、`--refresh-concepts`、
> `/api/concepts-rebuild` **三条出网入口都要挡**（只挡第一条时，一次 CLI 或页面按钮照样全量出网）。
> 缓存过期时请求线程**只后台点火、不等待**（否则一次 `/api/stock-tags` 挂 50 秒），
> 点火带 600 秒退避：MAC 半故障（连得上但板块命令报错）时不至于每只股票都重试一遍全量、打满线程池。
周期共 10 档（日 / 周 / 月 / 季 / 年 + 1 / 5 / 15 / 30 / 60 分钟），切档即**一次拉满**，不做按需回溯：
日线取 10 年 ≈ 2430 根（本地仅 41.4% 的标的够 10 年，不够就有多少给多少）；
周 / 月 / 季 / 年直接全量（600519 = 1270 / 302 / 102 / 26 根）；
分钟按本地 `.lc1/.lc5` 的滚动窗口取 120 个交易日（1 分 28800 根 ≈ 10MB，5 分 5760、15 分 1920、30 分 960、60 分 480）。
拉满不等于铺开：打开任一档的默认窗口只有一条口径（`web/js/chart.js` 的 `applyDefaultView`）——
屏上放最近 **360 根**（`DEFAULT_VIEW_BARS`）、末根贴右边缘，所以切周期只改变覆盖的时间跨度：
日线 ≈1.5 年、周线 ≈7 年、60 分 = 90 个交易日、1 分 = 1.5 个交易日；蜡烛粗细 = 数据区宽 ÷ 360
（1600px 视口 ≈4.3px/根），历史短到不足 360 根（月 / 季 / 年、次新股）就全部铺开。
更早的历史仍在内存，向左拖即可。旧口径是固定 2px/根（1600px 视口 ≈614 根），蜡烛密到看不出形态，
2026-11-03 改成数根数。
季 / 年线由本地**前复权日线**在 tv 侧重采样（桶 = 自然季 / 自然年，标签 = 桶内最后一个交易日，
OHLC 取首开 / 最高 / 最低 / 末收，量额求和），与 zg-core 的周月口径一致——`resample_dwm` 只到周月，本仓库不改 zg。
缠论覆盖除年线外的 9 档：季线自建 `RawBar(Freq::S)` 调 zg-chan 公开的 `assemble`
（zg 的 freq 表只到 D/W/M/F\*，而 `qualify_points` 会把级别名写进买卖点文案，借标成 M 会显示「月线」）；
年线本地最多 29 根（600519 = 26），低于缠论 60 根下限，**这一档只有 K 线**，顶栏「缠」置灰并写明原因；
次新股（如 300750 只有 35 季）同理，前端按根数预判，不发注定被拒的请求。
画线支持水平线（可拖动）/ 垂直线 / 趋势线 / 矩形 / 斐波那契回撤 / 价格线 / 文本，按标的 + 周期存盘；
另有临时测量工具：两点拉出区间，显示 Δ价 / Δ% / K 线根数 / 时间跨度，不落盘。
价格预警沿用 TradingView `user-price-alerts` 原生交互：鼠标在图上时右侧出现时钟+按钮，点一下在该价位添加；
预警以蓝色虚线与时钟图标标出，靠近时显示「名称 触及 价格 ×」标签，点 × 删除；蓝色虚线可直接上下拖动改价。
侧栏「价格预警」按价列出当前标的全部预警（含相对最新收盘的涨跌幅），可逐条删除或清空；
按标的存 localStorage，跨周期 / 刷新保留（只做图面标记，不做后台轮询或弹窗提醒）。
顶栏「缠」可显示 / 隐藏缠论图层（笔、中枢、买卖点），状态持久化，方便单独看其它指标；
侧栏「缠论买卖点」列表显示个股名称（全市场模式下名称下方附代码），点击行可直接切换标的；
侧栏「行业热度」显示 128 个二级行业的完整列表，可按热度升降序；**单击**行业 = 主图切到该板块的
日 / 周 / 月 / 季 / 年 K 线，**双击**才把侧栏摊成它的成分股列表，点成分股回到个股图。
三个横截面页签（行业热度 / 宽基指数 / 板块总览）都是这一套手势：行业热度与宽基指数
在页签里各写明一行提示，板块总览不挂常驻提示（挤占图表区，手势说明留在散点的悬浮
提示里）；双击的第二记走同码去重，不会白跑一整轮 `load`（bars+指标+缠论）。三处下钻摊开的是
同一张成分股表（`renderDrill` 一份渲染，涨跌列口径在 `memberPct` 归一：热度行给 `heat`、
指数成分股给 `pct`，同为当日涨幅），改一次列口径只改一处。行业与成分股数据来自本地共享快照
（横截面不逐股拉实时，盘中会标 `stale`），无网络请求。
同栏「宽基指数」页签列出上证指数、深成指、创业板、科创板、沪深300 / 500 / 1000 / 2000、
上证50、中证 A50 / A500 共 11 个指数；单击看指数 K 线、双击展开成分股（无成分股的指数显示提示）。
指数行情盘中走 TQ → 腾讯 → 东财（本地日线陈旧时自动 `refresh_kline`），收盘后读本地快照；
离线模式下中证 2000 / 中证 A50 若无本地日线会标为不可用。成分股仍读本地快照。
同栏「板块总览」页签展示 **128 个通达信研究行业二级**（与「行业热度」同一套 `industry_catalog.json`
目录，5587 只成员含北交所）的轮动地图与数据表格；表格行与散点圆点同样是**单击开板块 K 线 / 双击摊成分股**。

**轮动**（横轴=合成拥挤分位，五分量等权：成交额占比 / 20 日均振幅 / 60 日 β / 20 日量价相关 / 乖离率；纵轴 Rk6=6M 动量截面百分位）、

## 环境变量（run.sh 已内置，手跑二进制时才需要）

| 变量 | 默认值（run.sh 解析后的实际值） |
|---|---|
| `ZG_ROOT` | 仓库根目录（`run.sh` 里为 `$PWD`） |
| `ZG_VIPDOC` | 直读通达信：`<通达信安装目录>/vipdoc`（`run.sh` 默认取它探测到的客户端目录）；拷贝模式：`data/vipdoc` |
| `ZG_GBBQ` | 直读通达信：`<通达信安装目录>/T0002/hq_cache/gbbq`；拷贝模式：`data/tdx/gbbq` |
| `ZG_XDXR_CACHE` | `data/tdx_xdxr` |

`run.sh` 这三个行情路径**每次都会导出**，所以正常启动不用管。手跑二进制（不经 `run.sh`）
时它们才用 `zg-core` 的内置默认：仓库内 `data/vipdoc`、`data/tdx/gbbq`、`data/tdx_xdxr`
——这是「本地快照」口径，仓库不带行情，所以要么先跑 `TV_SYNC=copy ./run.sh` 生成快照，
要么自己 export 指到通达信目录。

**行情源默认直读通达信目录（2026-11-06 起）**：`./run.sh` 不再每次启动把行情拷进
`data/vipdoc`，而是直接读通达信安装目录下的 `vipdoc`——应用本来就只读它
（`run.sh` 把探测到的目录用 `ZG_VIPDOC` 导出，`paths.rs` 只负责接收）。

为什么改：DFZQ 盘后重写全部 9682 个 `.lc1`，每个文件是 173 个交易日的滚动窗口
（32 字节/分钟根，新的一天进来就把最老一天挤掉、整体前移 7680 字节），内容天天变；
而 rsync 本地默认是整文件搬运，于是每次启动都要搬完整的 11.5GB，跨两块 Windows 盘
约 2.4 分钟且**全程零输出**——看着像卡死（2026-11-06 这次启动就是这么被 Ctrl+C 掉的，
rsync 报 SIGINT code 20）。直读后实测端口 0.5 秒就绪、末根当天。

三种模式：
- **direct（默认）**：直读通达信目录，零拷贝。代价是没有本地稳定快照；DFZQ 盘中写盘时
  读 `.lc1` 可能读到半个文件（拷贝模式同样会拷到半个文件，这个风险不是 direct 独有）。
- **copy**：`TV_SYNC=copy ./run.sh` —— 增量同步进 `data/vipdoc` 后读快照，用于离线机或
  怕盘中写盘撞上。无更新的晚上也要 stat 一遍（lday+minline 约 14 秒）。
- **显式 `ZG_VIPDOC`**：调用方指定数据源，原样使用，不拷贝不改写。

本机没装通达信时自动回落 `data/vipdoc` 快照，功能完整只是数据停留在快照日
（回落会打警告，不静默）。手动强制对平：`TDX_VIPDOC=... TDX_GBBQ=... tools/sync-data.sh`
（`TDX_VIPDOC` / `TDX_GBBQ` 可指其它通达信目录）。旧的题材文件 block_gn.dat 随 gbbq
同目录读（只作 MAC 不可用时的回退；源头停在 2022-08-24，题材新鲜度靠 MAC 在线刷新保证）。

派生缓存在 tv 内**全自动再生**（不依赖 zg）：
- 行业目录：分类文件（tdxzs3/tdxhy.cfg）变化时 `tools/build-catalog.sh` 重生成
  （`tv --build-catalog`；run.sh 与 sync-data.sh 共用这一份逻辑）；
- 行业热度：服务启动检测过期 → 本地日线重算（约 35 秒，含除权日交易所口径修正；
  手动 `/api/heat-rebuild`）；
- 缠论扫描：服务启动检测过期 → 全市场本地重扫（约 1-6 分钟；手动 `/api/scan-rebuild`）。
- 唯一冻结的是指数成分股（源头在东财，半年调仓一次；指数 tab 已标注数据快照时间）。

## 实时链路（方案 C，2026-11-02）

默认开启，所有网络调用集中在 `src/live`（根文件 + `policy.rs` 降级链与合并语义、`source_local.rs` 本地 vipdoc、`source_mac.rs` MAC 取数）：

| 场景 | 数据源 | 说明 |
|---|---|---|
| 盘中日/周/月/季/年 | 本地全历史 + 远端**只补本地没有的日期**（白名单：**TQ → MAC（通达信扩展行情，不复权 + 本地事件法复权）**） | 本地 `.day` 已到最近交易日时**根本不问远端**（纯本地最干净）；本地落后（盘中本地只有 T-1）才问远端补缺口。同日以**本地为准**（远端覆盖本地 = 把 11.6 年历史整体换基，日 K 与分时图就此错基），远端补进来的那几根锚在最新价，与本地同基、接缝连续。公开源（同花顺/腾讯/东财/datahub）已从日线链移除：复权口径与本地不同源，留着只是白跑网络 —— 与其拿异基源凑一张「看起来更新」的图，不如回落本地并如实标 `stale`。周/月/季/年在这份日线上重采样，保住 10 年+ 深度。涨跌幅用**前复权**末两根收盘之比（除权日不会算错） |
| 收盘后 | 本地 vipdoc 优先，末根 ≥ 最近交易日才用 | 本地陈旧时自动切同一套远端链，并在响应 `meta.stale` 标出 |
| 分钟线 | 本地（15 分钟新鲜度门禁）→ TQ → **MAC（通达信扩展行情）** → 腾讯 → tdx-master；**1 分钟档除外：只读本地 `.lc1`** | 远端只回最近若干根，与本地历史按时间合并，保留 120 日深度；合并前先归一到本地口径（见下）。1 分钟档走离线采集（2026-11-02 用户定）：客户端盘中自己连续写 `.lc1`，且 1 分是唯一「远端与本地按根对齐会看出接缝」的档；本地落后一个交易日时**如实标 `stale`**（顶栏徽标「1 分钟 · 本地采集 截至 …」标黄），不补远端 |
| 指数 / 板块 | 本地 → TQ（>15 天陈旧才 `refresh_kline`）→ 腾讯 → 旧本地 | 季/年用本地全历史 + 远端最近几根合并，避免历史被截断 |
| 实时报价 | 批量 `TQ(front)` → 单票五源链 | 3s 进程内缓存；`/api/quote`、`/api/live`、`/api/market-status` |

远端序列并入本地前先校验兼容性（`src/live/policy.rs::remote_mergeable`）：含非正价格、或与本地重叠段
偏差超限的整段丢弃。判据三条，缺一不可：

- **两段采样**（最旧 200 根 + 最近 200 根，各自判定，任一段超限即拒）。前复权一律锚在最新价，
  所以任意两个复权基在「当下」必然重合，基差只随历史深度放大（实测 600346：东财 vs 本地在最近
  200 根中位差 1.61%，在 2013-2015 那段是 228%）。只看一段：最近段会漏放老历史错基，
  最旧段会漏放接缝处的新错基。
- **同精度比较**（两边都四舍五入到分）。远端多为 2 位小数、本地 qfq 是 3 位；老历史被分红压到
  1.5 元级时，半分的相对差就是 0.33%，高于 0.1% 的相对门限 → 纯相对判据会**误杀同基源**
  （实测 600346 vs TQ：未对齐精度时最旧 200 根中位 0.1316%，对齐后 0.0000%）。
- **绝对容差下限 1 分 1 毫**（容差 = max(0.1% × 价格, 0.011 元)）：低于一个价格最小变动单位的
  基差本来就测不出来，仙股不至于连半分钱的噪声都容不下。

东财 `fqt=1` 是减法前复权，600519 2014 年会算出 -155；腾讯是乘法 qfq，但与本地 gbbq 事件法
**不是同一套口径**：实测中位偏差 000338 0.53%、600519 0.25%、000001 0.09%、300750 0.04%，
而 TQ 的 `dividend_type=front` 与本地**逐位同基**（实测 6 只股票、2900 根重叠，两段中位占容差 0.000 倍）。
基差会让日 K 图与分时图对不上（实测 000338 2026-08-10 分钟末根 30.9256 vs 日线 31.19，差 0.85%），
所以降级源宁可拒掉、回落本地并标 `stale`（显式陈旧好过静默错基）。盘中缓存 TTL 一律 15s
（午休 60s），坏结果不会长时间驻留；TQ 护栏拒绝（连续切周期的 2s / 3 连发配额）时，
若 TQ 在线则等 2.1s 重试一次再退化。

**远端分钟主源：通达信 MAC（扩展行情）协议，Rust 自实现**（`src/tdxmac.rs`）——
标准协议的 K 线命令在公共行情服务器上**全为空**（easytdx / pytdx / tdxrs 实测 0 根，
而 `get_security_list` 能回 1000 条 → 链路通、服务器不供 K 线），TQ 的分钟（period=1m）也返回空，
所以远端分钟原本只剩腾讯（未复权、无成交额、每天多一根 09:30 伪 bar）。MAC 协议可供数：

| 项 | 实测 |
|---|---|
| 轴 | 09:31–15:00、单日 240 根，与本地 `.lc1` **完全同轴**（无集合竞价伪行） |
| 成交额 | 真实成交额（元）；腾讯恒 0 |
| 复权 | 服务端 `fq=1` 前复权，与 TQ/本地 gbbq 基一致（实测偏差 0.0000%），**不再叠前复权** |
| 深度 | 约 10~17 个交易日（700 根/页 × 最多 6 页），更早由本地 `.lc1` 覆盖 |
| 主机 | `121.36.248.138` / `123.60.47.136` / `121.37.207.165`（端口 7709）；**按固定顺序取第一台连通的**，实际主机写在 `meta.detail`（如 `mac@121.36.248.138`） |
| 日线 | MAC 的**不复权**日线与本地 `.day` **逐位一致**（实测最大收差 0.0000）→ 取不复权 + 用本地同一套除权事件复权，即与本地日线同源。TQ 不可用时它接管日线（末根仍是今天，与 TQ 模式逐根全等） |

各 MAC 主机的**同日汇总一致**（且与本地 `.lc1` 一致），但**桶级分桶有微差**
（tick 归桶时序不同，个别 5 分钟桶差 1~2 手）——所以 `tools/mac_parity.py` 按 `meta.detail`
连**同一台**再逐根对表，否则会把服务器差异误判成实现不一致。

**MAC 与本地的复权基不是同一套**：MAC 服务端的前复权因子与本地 gbbq 事件法在除权日当天差 0.33%
（实测 000338 2026-10-08：MAC 24.34 vs 本地/TQ 24.26），且随历史累积（日线 250 日中位差 2.28%）。
所以 MAC 分钟并入本地前做**逐日比例缩放**（同一天内所有价乘同一系数，形状不变、只平移基），
把接缝偏差从 0.33% 压到 0.02%；`tools/mac_parity.py` 的判据也相应改成
「vol/amount 逐根全等 + close 在同一天内比值恒定」。

**分钟线的三处口径归一**（`src/live/policy.rs` 的 `normalize_axis` / `qfq_align` + `minute_mergeable` /
`merge_minute`）——远端分钟源
与本地 `.lc1` 不是同一条链，直接按时间串合并会串味：

| 差异 | 现象 | 处理 |
|---|---|---|
| 时间轴 | 腾讯 m1 每天多一根 `09:30` 集合竞价行（O=H=C），本地是通达信口径（09:31 起 240 根/日） | 丢掉该行，并把它的成交量并进首根 `09:31`（通达信把竞价量记在首根上，否则当日分钟量少一个竞价量）。MAC 本身即通达信轴，无需此步（保留给降级的腾讯源） |
| 复权基 | 腾讯分钟是未复权价，本地分钟是前复权价；除权股在远端窗口内会整体偏高一个除权因子（实测 000338 在 2026-10-08..10-22 偏高 2.5%），接缝处出现假跳空 | 用同一套除权事件（zg-core `adjust::adjust_bars`，前复权锚在末根=最新价）把远端换算到本地复权基；再过兼容门（重叠段中位偏差超限整段丢弃远端，退回本地并标 `stale`）。TQ / MAC 服务端已是前复权，**不再叠前复权** |
| 成交额 | 腾讯分钟没有成交额字段（恒 0） | 同分钟有本地值就沿用本地成交额；远端独立日（今天）本地无数据时为 0，并在服务端日志按 (代码, 日期) 提示一次。MAC 源自带成交额，无此问题 |

`tools/final_check.sh` 有对应的口径门：每天不超过 240 根，且已收盘交易日的分钟末根与同日日线
收盘偏差 ≤1%（除权股也在内）。

前端每 **15s** 递归 `setTimeout` 走一拍（`visibilityState === 'visible'` 且当前是个股才取数），
但**任何实时请求的最短间隔都是 300s**（`LIVE_MS`）：报价、大盘状态、分钟线整段重取各有一道 300s 闸，
心跳本身不发请求。日/周/月/季/年用报价更新末根，所以末根价最多滞后 5 分钟；
1 分钟档连报价都不发（该档只读本地 `.lc1`，徽标改报「1 分钟 · 本地采集 截至 …」，
本地落后最近交易日就标黄并加「本地数据未更新」，提示去做通达信盘后下载）。
切股 / 切档 / 点「刷新」都是一次 `load()`，会把报价闸重开，下个心跳（≤15s）就补上，不让人等满 300s；
报价请求失败时不占这个闸（下个心跳即重试，不会因为一次 TQ 抖动让徽标黄足 5 分钟）。
非交易时段按最近一次 `/api/bars` 的 `meta` 报来源与日期：图来自远端时显示
「非交易时段 · TQ-Local 2026-11-04（本地 2026-11-03）」；来源是本地时写
「本地DFZQ 截至 X」，X 取**图表自己的 `as_of`**（不拿指数的日期顶替——个股 .day 停了就是停了）；
徽标悬浮显示 `meta.detail`（远端源为何被拒 / 并入了哪个源），以前这些原因只在服务端日志里；
`TV_LIVE=0` 显示「离线模式」，数据源全挂时标黄 `stale`。

横截面（行业热度 / 板块总览 / 缠论扫描）本轮**不逐股拉实时**，只加 `session` / `stale` / `as_of` 标记，
板块总览的状态行会把标记**显示出来**（红字「盘中 / 陈旧」，悬浮给 `stale_reason`）：交易日历取自
基准 `sh000300.day` 这一个文件，它落后行业侧末根时 `as_of` 退一天、所有「自身序列派生」列按新鲜度
门禁整体置空——数值没错但界面看着像坏了，所以把原因摊开；同日有 bar 的行业数不足满覆盖日 90% 时
成交额占比（c1）整列不出数，状态行的 `127/128` 就是这件事的可见度。
Tick / 五档 / Level-2 不做。TQ 的两个致命接口（`get_market_snapshot`、`get_scjy_value` 带日期区间）
在 `crates/zg-market/src/tq.rs` 的拒发层拦死，`final_check.sh` 另有静态扫描。

关闭方式：`TV_LIVE=0 ./run.sh`（或 `TV_OFFLINE=1`）→ 与旧版完全一致的纯本地行为，`parity.py` 对表用这个模式。

## 换机器 / 重建

```bash
./run.sh                         # 编译 → 选行情源 → symbols.json bootstrap → 启动
```

行情数据默认**直读通达信目录**（安装目录下的 `vipdoc`），不落本地副本，
换机器只要装好通达信就能跑。想要本地稳定快照时用拷贝模式：

```bash
TV_SYNC=copy ./run.sh            # 增量同步进 data/vipdoc 后读快照（约 13GB）
```

或手动拉一次：`TDX_VIPDOC=... TDX_GBBQ=... tools/sync-data.sh`。
`data/vipdoc` 等快照不进 git，也不再是启动的前提。
