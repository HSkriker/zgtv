## 第一部分：模块地图与来源

### 1.0 一句话总览

| 层 | 是什么 | 来源 |
|---|---|---|
| `src/` | tv 自有后端（看图服务 + 实时取数编排） | 自有 |
| `crates/zg-{core,chan,market,api}` | 数据/缠论/行情/HTTP 四层 | 自有仓 `gs/zg` 的 Rust 层整包内嵌（非外部开源）；该仓仍是独立的另一个项目，但**不再是 tv 的依赖**（构建/运行都不引用它） |

| `web/js/` 三个 primitive | 价格预警 / BOLL 填色带 / SMC-PA2 算法 | TradingView `plugin-examples`（Apache-2.0）与 `smart-money-concepts` 0.0.27（MIT）的移植 |

### 1.1 `crates/` —— 内嵌的 zg 四层 crate

**来历**：2026-11-01 从平级仓 `gs/zg`（其 Rust 层目录 `zg-rs/crates/`）整包 `cp -a` 拷入，包名未改；唯一结构性改写是把原 workspace 的 `.workspace = true` 字段内联。证据：`Cargo.toml:24`、`README.md` 的「目录」节、`docs/工单-初级工程师.md` 头部变更记录（开发记录，公开仓不携带，见 §3.2）。四个 crate 的 `Cargo.toml` 自报 `license = "MIT"`，那是 zg 作者（与你同一授权主体）给自己标的，**不是**某个上游开源库的许可；仓根 `LICENSE` 与根包 `license` 字段已于 2026-11-03 统一为 MIT。

**这四层本身是 Python 的 Rust 移植**，crate 内逐文件写明了移植源（这些注释是判据来源，改代码前要当回事）：

| crate | 职责 | 自陈移植源 |
|---|---|---|
| `zg-core` | `.day/.lc1` 读取、前复权、重采样、kcache 二进制缓存、gbbq/xdxr 除权事件 | `modules/zgcore`（Python 包）逐值等价：`lib.rs:1`、`reader.rs:1`、`adjust.rs:1`、`resample.rs:1`、`kcache.rs:1-3`（与 `zgcore/bars/cache.py` 字节级兼容）、`paths.rs:1` |
| `zg-chan` | 缠论：L1 官方信号 + L2/L3 规则裁定 + 全市场买点扫描 | `modules/czsc_bridge/*`：`lib.rs:1`、`official.rs:1-3`、`method.rs:1`、`service.rs:1`、`scan.rs:1` |
| `zg-market` | 外部行情源与降级编排、TQ、同花顺、报价、蜡烛形态引擎、行业热度 | `modules/zgapp/*` + `modules/market/*` 逐文件清单见 `lib.rs:3-6`；`candles.rs:1-4`、`tq.rs:1`、`industry.rs:1`、`mac.rs:1-3`、`kbuild.rs:1-4`、`ths.rs:1-3`、`consts.rs:1`、`canon.rs:1-3` |

**判据权威不是 zg 而是 czsc**：`zg-chan/src/lib.rs:7-9` 明写「直接依赖 `czsc-* =1.0.2`（P0.5 已验证与 Python czsc 1.0.2 同源），**不得自建判据、不得"优化"上游语义；所有口径以 Python oracle 为准**」。

**tv 侧确有源码级改写**（"内嵌即原样"不成立，改动都留了注释）：

- `crates/zg-core/src/reader.rs:43-47`：笔数上限表按 tv 图窗重算（D/W/M=500、F1=5000…），注明「zg 侧若图窗不同需按其窗口另算（**回同步事项**）」
- `crates/zg-core/src/adjust.rs:370-371`：因子缓存键补 gbbq mtime，「zg 上游同病，tv 内嵌副本先修」
- `zg-api/src/aux.rs → aux_svc.rs` 改名（Windows 保留名 `aux`），引用点同步调整
- 四个 crate 的测试把仓根上跳从三级改两级（`bars_parity.rs:18`、`registry_parity.rs:16`、`gate1_fixtures.rs:229`、`candles_golden.rs:11`），注释保留了「zg 原件在 zg-rs/crates/ 下需三次上跳」这句历史
- 公开仓适配（2026-11-03）：夹具/行情缺失时打印 SKIP 而不是变红（见 §2.6）

而「不改 zg」的承诺只针对具体一处口径：季线重采样与 `Freq::S` 走 tv 自建（`Cargo.toml:29-30`、`src/bars.rs`、`src/chan.rs:30`），不能推广成"整个 crate 未被修改"。

### 1.5 「看着像密钥、其实是公开协议常量」的资产

上传时最容易被误判成凭据泄漏的三样，逐个说明：

- **`crates/zg-core/src/gbbq_keys.bin`（4176 字节，tracked）** —— 不是密钥。`gbbq.rs:6-7`：「查表常量 `gbbq_keys.bin` 提取自 vendored `easy_tdx/offline/gbbq.py::_HEX_KEY`（4176 字节，纯数据表）。改动该表会改变解码结果」。它是通达信 `gbbq`（股本变迁）文件记录前 24 字节做 3 轮 XOR 置换所用的查表，属公开协议的反混淆表；本机 `easy_tdx/offline/gbbq.py::_HEX_KEY` 解 hex 后与该 `.bin` 逐字节全等（2026-11-03 实测），easy-tdx-plus 为 MIT、其 NOTICE 自陈该 key 移植自 pytdx —— 原文的「MIT/Apache 双许可」中 Apache 无据，`gbbq.rs:6-8` 已按实测更正，署名见 `THIRD-PARTY-NOTICES.md` §2.5；`gbbq.rs:34-58` 逐行复刻 Python 的偏移（`0x44`/`0x448`/`0x48`/`0x848`/`0xC48`）。
- **`src/tdxmac.rs:46-53` 的 MAC 主机 IP 与端口 7709** —— 公开行情服务器地址表（easy-tdx-plus 的 `MAC_HOSTS` 常量），非凭据。
- **`crates/zg-market/src/tq.rs` 的 `http://127.0.0.1:17709/`** —— 本机通达信 TQ 量化接口，`TQ_URL` 可覆盖。

**真凭据（同花顺 hithink key）不在仓内也不在 git 历史里**：`crates/zg-market/src/ths.rs:22` 的 `api_key()` 只按 `HITHINK_FINANCE_API_KEY` → `HITHINK_API_KEY` → `THS_API_KEY` → `%APPDATA%\hithink-finance\credentials.env` → 本机 `ths_key.txt` 顺序读，且注释规定「返回的 key 只用于请求头，任何日志/错误消息都不允许包含它」。`.gitignore` 另加了 `ths_key.txt` / `credentials.env` / `.env` / `*.key` 的护栏。

### 1.6 crates.io 依赖与许可面

- **缠论判据的唯一权威是 czsc**：上游仓库 <https://github.com/waditu/czsc>（Python 本体与仓内 Rust 端口同一个仓库、同一个 MIT 授权）。本机 `~/.cargo/registry/src/*/czsc-{core,signals,ta,utils,derive,signal-macros}-1.0.2/Cargo.toml` 的 `repository` 字段全部指向它，`license = "MIT"`；包内不带 LICENSE 文本，署名写在 `THIRD-PARTY-NOTICES.md` §2.6。

## 第二部分：怎么用

### 2.0 最短链（WSL）

```bash
cd <repo>
TDX_VIPDOC=... TDX_GBBQ=... bash tools/sync-data.sh   # 可选：强制与本机通达信对平（默认启动直读，不做拷贝；源必须显式给）

# 浏览器打开 http://127.0.0.1:8790
bash tools/tvctl.sh status      # 探活
./tools/final_check.sh          # 终检（服务需在跑）；加 --build 连编译+测试一起门
```

### 2.1 `run.sh` 做的七件事

1. `cd` 仓库根并 `export ZG_ROOT="$PWD"`（`run.sh:4,6`）。
2. **钉时区** `export TZ="${TZ:-Asia/Shanghai}"`（`run.sh:9`）——交易日历/盘中判定用 `Local::now()`，换 UTC 会让末根形态与指数新鲜度漂移。
3. **构建判定**：`target/release/tv` 不存在，或 `src crates Cargo.toml Cargo.lock` 任一新于它 → `cargo build --release`（`run.sh:11-25`）。**必须排在行业目录重生成之前**：build-catalog.sh 要用同一个 release 二进制的 `--build-catalog` 重生成行业目录，二进制不存在时它只能跳过。
4. **选行情源**（`run.sh:27-113`）：默认源 `TDX_VIPDOC=<通达信安装目录>/vipdoc`、`TDX_GBBQ=<通达信安装目录>/T0002/hq_cache/gbbq`。**2026-11-06 起默认直读通达信目录、零拷贝**（应用本来就只读它，`run.sh` 把探测到的目录用 `ZG_VIPDOC` 导出；`crates/zg-core/src/paths.rs` 的内置默认是仓库内 `data/vipdoc`）——原设计是每次启动 rsync 整份拷进 `data/vipdoc`，但 DFZQ 每天重写全部 9682 个 `.lc1`（每个是 173 交易日的滚动窗口，每天整体前移 7680 字节），整文件搬运每次要搬 11.5GB、跨两块 Windows 盘约 2.4 分钟且全程零输出，看着像卡死（当天这次启动就是被 Ctrl+C 掉的，rsync 报 SIGINT code 20）。三种模式：①**direct（默认）** 直读通达信目录；②**copy**（`TV_SYNC=copy`）增量同步进 `data/vipdoc` 后读快照，判定「新数据」用 `data/.last-sync` 与 mtime 比：全量扫三市场 `lday/*.day` **和 `minline/*.lc1`**（`find … -newer -print -quit`），再比 `gbbq`/`block_gn.dat`/`tdxzs3.cfg`/`tdxhy.cfg`——**必须含 minline**：DFZQ 约 15:57 写 `.day`、16:03 才写 `.lc1`，只查日线会让「同步跑在两次写入之间」那天永久漏掉分钟线（2026-11-03 事故：SH/BJ 分钟线停在前一交易日），代价是无更新的晚上也要 stat 一遍（lday+minline 约 14 秒）；③**显式 `ZG_VIPDOC`** 原样使用，不拷贝不改写。本机没有通达信目录时回落 `data/vipdoc` 快照并打警告（不静默）。
5. **导出数据路径 + 存在性校验**：`ZG_VIPDOC`/`ZG_GBBQ`/`ZG_XDXR_CACHE` 任一不存在即报错退出并提示覆盖方式（`run.sh:113-131`）。
6. **行业目录重生成**：`tools/build-catalog.sh` 判 `tdxzs3.cfg`/`tdxhy.cfg` 是否比 `modules/market/industry_catalog.json` 新 → 跑 `tv --build-catalog`（只读 hq_cache，秒级）。直读模式下没有 sync-data.sh 兜底，这一步必须在这里做，否则行业目录永远停在旧口径。run.sh 与 sync-data.sh 共用这一份逻辑，不分叉。
7. **标的表 bootstrap**（`run.sh:138-151`）：`data/market/stocks.json` 缺失时先 `tv --fetch-stocks` 联网拉一次（无网则提示手动放一份，已有 symbols.json 时仍可启动）；`data/symbols.json` 缺失或比 stocks.json 旧时跑 `tv --gen-symbols`。
8. `exec target/release/tv`，打印 `http://127.0.0.1:8790`（`run.sh:153-154`；端口常量 `src/main.rs:29`）。

绕过 run.sh 手跑二进制的最小环境（`ZG_VIPDOC` 也可直接指通达信目录，与 run.sh 默认口径一致）：

```bash
export TZ=Asia/Shanghai ZG_ROOT="$PWD"
export ZG_VIPDOC="<通达信安装目录>/vipdoc" ZG_GBBQ="<通达信安装目录>/T0002/hq_cache/gbbq" ZG_XDXR_CACHE="$PWD/data/tdx_xdxr"
TV_LIVE=0 ./target/release/tv          # 纯离线
```

### 2.5 服务形态与前端使用面

- **tv 只有一个服务：`127.0.0.1:8790`**（端口常量 `src/main.rs:29`，路由分派 `src/router.rs:22`）。路由族按功能分组：健康与状态（`/api/health`、`/api/market-status`）、实时（`/api/quote`、`/api/live`，离线返 503）、K 线（`/api/bars`、`/api/board-kline`）、指标（`/api/ind`）、缠论（`/api/chan`、`/api/scan`）、横截面（`/api/sector-overview`、`/api/heat`、`/api/market-indices`、`/api/index-constituents`、`/api/heat-rebuild`、`/api/scan-rebuild`）、标签与题材（`/api/stock-tags`、`/api/concepts-stats`、`/api/concepts-rebuild`）、画线（`/api/drawings` GET/POST）、标的表（`/api/symbols`）。
  鉴权口径：**无 token**（本机服务），靠只绑 127.0.0.1 + Host 头本地校验（防 DNS rebinding）+ 副作用端点的跨站防护（`Origin`/`Sec-Fetch-Site`）。
- **五个一次性 CLI 入口**（argv 判定，不是子命令；集中在 `src/cli.rs`，命中即跑完退出——成功 0、失败 1）：`tv --refresh-concepts`（全量刷概念缓存）、`tv --fetch-stocks`（联网拉全市场股票列表）、`tv --gen-symbols`（生成 `data/symbols.json`）、`tv --build-catalog`（重生成行业目录）、`tv --replay-overview <out.csv> [days=750]`（板块总览历史回放 CSV）。
- **8786 / 8787 与 tv 无关**：那是内嵌 `zg-api` 自带的独立 bin（8786 主站 + 同进程线程拉 8787 行情监控）。tv 只把它当**库**复用 HTTP 骨架与防护件，`./run.sh` 全程不启动 8786/8787，也不走它的 routes。`zg web`、`zg xdxr sync`、`zg kcache build` 这些命令属于已不存在的上游 `gs/zg`，**本仓没有名为 `zg` 的二进制**，文档里别照抄。
- **前端功能定位**：侧栏面板集中在 `panels.js`（缠论买卖点、行业热度、宽基指数、板块总览含散点四模式与放大窗、自选、预警列表）；图层开关走各自齿轮浮层（`candles.js`「形」、`ind.js` 指标、`pa2.js` SMC、`volume-profile.js` VP、`chan.js` 缠论）；图上右键菜单 `context-menu.js`；手势：滚轮上下翻板块（横截面页签停在板块层时）、`Shift`+滚轮缩放周期长短、`↑/↓` 缩放、双击下钻成分股、`Home` 适配全图。
- **持久化分两类**：图面偏好与预警在 **localStorage**（键前缀 `tv.`，如 `tv.chan.on`、`tv.ind.params`、`tv.vp.range`、`tv.ov.mode`、`tv.watch`、`tv.alerts.<code>`）；**画线在服务端** `data/drawings.json`（按 `code|period` 存，写用 tmp+rename 原子替换，文件损坏时拒绝覆盖，防止一次写坏抹掉其它标的）。

### 2.6 测试怎么跑，以及「SKIP」的语义

```bash
cargo test --workspace                                   # 全部成员 + 根包
ZG_ROOT="$PWD" cargo test --release --offline -p zg-core -p zg-market -p zg-chan   # final_check 用的口径
```

- `cargo test`（不带 `-p`）只跑根包 `src/` 内联单测，**不带成员 crate**；`candles_golden` 这类必须 `-p`。
- 成员 crate 测试要**显式注入 `ZG_ROOT`**，否则 `zg-chan` 的测试会把 vendor 目录按测试二进制所在目录推成 `target/.../modules/`，除权缓存过期时报「vendor 目录不存在」（`final_check.sh:120-123`）。
- 行情/夹具依赖与缺失行为：

| 测试 | 前置 | 缺失时 |
|---|---|---|
| `zg-core/tests/bars_parity.rs` | `eq/fixtures/tdx` + `eq/golden/rust/core_golden.json.gz` | 9 个用例打印 `SKIP bars_parity` 后返回（守卫 `fixtures_ready()`，每个用例首行 `need_fixtures!()`） |
| `zg-market/tests/candles_golden.rs` | `eq/golden/wsl/20261027/api/` | 3 个用例 `SKIP candle 金标`（守卫只看**目录**在不在；目录在但缺单文件仍 panic，防静默漏检） |
| `zg-market/tests/gate1_fixtures.rs` | `tests/fixtures/*.http` + `data/market/stocks.json` | `SKIP 门 1 录播对表`（`load_fixtures` 目录不存在返回空） |
| `zg-chan/tests/bi_window_causality.rs` | `data/vipdoc/sh/lday/sh600519.day`，无则用通达信客户端目录（`TV_TEST_VIPDOC` 可覆盖）；**另需 `data/tdx/gbbq`** | vipdoc 与 gbbq 任一缺就 `SKIP 笔窗口因果性`（装了通达信但没导数据的机器上 vipdoc 在、gbbq 不在，公开 clone 即如此） |
| `zg-chan/tests/registry_parity.rs` | `eq/golden/rust/{signals_prod102,parity_params}.json`（**在库**） | 无守卫，照常跑 |
| `zg-api/tests/live_alerts.rs` | 临时目录，不读行情 | 无守卫，照常跑 |

实测：本机（数据在位）与公开 clone（数据不在位）`cargo test --workspace` 都是 **exit 0 全绿**，差别只在上面四组打印 SKIP。

- **公开 clone 上 `tools/final_check.sh` 不会全绿**，这是已知的、有意的：`§3 产物`要求 `data/symbols.json` 在库（`final_check.sh:94`，需自备数据后生成），而 `§5` 里若干独立重算门调的是 `target/qy-parity.py`、`target/ind-parity.py`、`target/macd-check.py`、`target/pa2-parity.mjs` 这些**被 `.gitignore` 忽略的 oracle 脚本**（`final_check.sh:462,634,644,286`），脚本不在时走 `bad` 分支而不是 skip。要公开可用的完整自检，需把这些证据脚本从 `target/` 迁进一个入库目录（见 §3.3）。
